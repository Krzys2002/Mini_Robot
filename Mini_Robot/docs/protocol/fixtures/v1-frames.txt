# Protocol version 1 byte vectors shared by both endpoints (#161).
#
# The desktop codec tests (#66, tests/transport/BleProtocolVectorsTest.cpp) and the
# firmware codec tests (#161, firmware/codecell-c6/tests/ProtocolCodecTest.cpp) both
# read this file. A change here changes the v1 contract: version 1 is frozen, so
# existing lines must never be edited (robot-protocol.md, "Version evolution").
#
# Format, one vector per line:
#   <name> <kind> <source> <key>=<value> ... | <hex bytes in transmission order>
# kind:   stop, velocity, estop, clear_estop (desktop to robot);
#         telemetry, result, robot_info (robot to desktop).
# source: published = the robot-protocol.md "Example frames" table (#64);
#         derived   = built from the published layouts to cover sentinels and extrema.
# Values use the wire units and JSON key names of the spec. `null` is an unknown value
# (the 0xFFFF / 0x8000 sentinels) or, for last_seq, hasAcceptedCommand clear.
# Command vectors outside the limits of robot_info_id7 must be rejected by the desktop
# encoder and decode as frames whose range check fails on the robot.
